# Высоты зданий из Overture Maps: проверка

Проверка 2026-10-20: могут ли высоты или этажность из [Overture Maps](https://overturemaps.org/) заменить константу «2 этажа» для домов, у которых в OpenStreetMap нет ни `building:levels`, ни `height`.

## Как сравнивали

- **Overture:** выпуск `2026-09-23.1`, тема `buildings`, тип `building`, GeoParquet из `s3://overturemaps-us-west-2` через DuckDB с фильтром по `bbox` города (`cities.config.mjs`). Взяты `height`, `num_floors`, `sources[].dataset` и контур.
- **OSM:** `data/<город>/buildings.json` проекта. Эталон — дома с `building:levels` или `height`: высота из `height`, иначе этажи × 3 м, как в расчёте.
- **Сопоставление:** контур OSM ↔ контур Overture с наибольшей площадью пересечения, если она не меньше половины меньшего из двух контуров.
- **Метрики — как в проверке GHS-BUILT-H:** корреляция высот, средняя абсолютная ошибка в метрах и та же ошибка у константы «2 этажа» (6 м). Высота Overture — `height`, иначе `num_floors` × 3 м.

## Вывод

Не подключаем. В Тивате и Которе Overture не добавляет ни одной высоты: все высоты и этажности у него из того же OpenStreetMap (поле `sources`, совпадение до сантиметра), а у домов, которым этажности не хватает, их нет и в Overture. Контуры Overture без высоты: в Тивате 3 125 из OSM и 1 285 из Microsoft ML Buildings, в Которе 3 545 и 795 — ML-контуры здесь все без высоты и этажности. Скрипт сравнения — разовый, в репозиторий не входит: запрос DuckDB к выпуску по bbox и сопоставление контуров через shapely.
